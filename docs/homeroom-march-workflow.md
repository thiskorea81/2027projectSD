# 3월 담임 업무 정리와 간소화 방안 (v0.1 초안)

> 학교 메신저 대체 시스템 — 작성일 2026-11-22
> 관련 문서: [기능 명세서](./functional-spec.md), [DB 설계](./db-design.md)
> 대상: 고등학교(고교학점제) 담임교사. 2027학년도 3월 적용을 목표로 한다.

## 0. 요약

- 3월 담임 업무는 **"수합·확인·입력"이 대부분**이다. 동의서·신청서를 걷고, 빠진 학생을 찾고, 결과를 NEIS나 공문으로 옮기는 일이 반복된다.
- 여러 부서가 같은 시기에 각자 메신저로 "○일까지 걷어 주세요"를 보내기 때문에, 담임은 마감을 메시지 속에서 찾아야 한다.
- 이 문서는 (1) 3월 담임 업무를 **시기별 체크리스트**로 정리하고, (2) 시스템에서 **"3월 담임 업무 팩"으로 할 일을 자동 생성·추적**하는 방식, (3) **결석신고서·교외체험학습 서류를 종이→스캔→공문 상신하는 학교**를 위한 간소화 흐름을 제안한다.
- 원칙: **NEIS가 원본이다.** 이 시스템은 NEIS를 대신하지 않고, NEIS·에듀파인에 넣기 전까지의 수합·확인·마감 관리를 맡는다. 학생은 **학번만 저장**한다(이름 저장 안 함).

### 2.6 NEIS 입력 관련 주의 (2026 기재요령 기준, 2027년 재확인 필요)

- 출결은 **결석·지각·조퇴·결과**를 **질병·미인정·기타**로 나눠 입력한다. 출석인정 결석은 출석으로 처리하고 사유·일수를 적지 않는다.
- 질병·미인정 결석과 지각·조퇴·결과의 **사유 입력 여부·기준은 학교장이 정해 학교 안에서 같게** 적용한다. 질병 사유는 개인정보 보호가 필요하면 적지 않는다.
- 학교폭력예방법 등에 따른 출석정지로 인한 미인정 결석은 사유를 입력하지 않는다.
- 결석·지각·조퇴·결과가 한 번도 없으면 특기사항에 "개근".
- 교외체험학습은 학교장 허가 시 출석인정 결석이며 학생부 어느 항목에도 입력하지 않는다.
- 진로활동 특기사항 500자, 행동특성 및 종합의견 300자(2026 기준). 3월에 쓰는 관찰 메모도 이 분량을 염두에 둔다.

## 3. 무엇이 담임을 힘들게 하는가

1. **마감이 메시지 속에 흩어져 있다.** 같은 주에 5~6개 부서가 각자 "○일까지"를 보낸다. 담임은 메시지를 다시 찾아 마감을 확인한다.
2. **누가 안 냈는지를 손으로 추적한다.** 서류마다 명렬표에 체크하고, 담당 부서는 반별로 "몇 명 남았나요?"를 다시 묻는다.
3. **같은 정보를 여러 번 옮긴다.** 종이 → 담임 체크 → 부서 엑셀 → NEIS 또는 공문.
4. **결석·체험학습 서류는 단계가 많다.** 신청 → 승인 → 실시 → 보고서 → 출결 반영 → 증빙 보관/상신. 단계 하나라도 빠지면 미인정 결석 처리 문제가 생긴다.
5. **종이 서류를 스캔해 공문으로 올리는 학교**는 스캔·파일명 정리·PDF 합치기·내부결재 상신까지 담임이 직접 한다.

## 4. 시스템에서의 간소화 방안

### 4.1 "3월 담임 업무 팩" — 할 일 자동 생성 (F-NOTI 확장)

- 교무부(또는 시스템 관리자)가 매년 **업무 팩 템플릿**을 관리한다. 템플릿은 §2의 각 항목을 한 줄씩 가진다.
  - 항목: 제목, 담당 부서(작성 주체), 대상(예: 1학년 담임), 마감 규칙, 첨부 양식, 학생별 수합 여부, 결과 입력처(NEIS/공문/부서 제출).
  - **마감 규칙은 학사일정 기준 상대 날짜**로 쓴다. 예: `개학일 + 4일`, `학부모총회일 - 14일`, `매월 말일 + 3 업무일`. NEIS 학사일정(F-CAL)이 들어오면 실제 날짜가 자동 계산된다.
- 2월 말에 교무부가 "2027 업무 팩 발행"을 누르면, 각 항목이 **담당 부서 이름으로 된 할 일**이 되어 대상 담임에게 간다. 부서가 메신저로 따로 보낼 필요가 없다.
- 부서 담당자는 발행 전에 자기 항목의 마감·양식만 고친다. 작년 팩을 복제해 시작하므로 매년 처음부터 만들지 않는다.
- 담임 화면: **"이번 주 할 일"** 목록(마감순) + 3월 전체 달력. 메시지함이 아니다.
- 부서 담당자 화면: **반별 진행률표**(예: 1-1 28/30, 1-2 완료…). 미완료 반의 담임에게만 재알림.
- 질문 자동응답(F-QA): "기초조사서 언제까지야?" → 업무 팩 데이터에서 마감과 담당자를 답한다.

### 4.2 학번 수합 체크 (학생별 제출 여부)

- 수합이 필요한 할 일은 **학번 × 제출 여부** 체크표를 가진다. 상태: `미제출 / 제출 / 해당없음`.
- 담임이 체크하면 부서 담당자 진행률이 바로 바뀐다. 부서가 반별 집계를 따로 받을 필요가 없다.
- 서버에는 **학번과 제출 여부만** 저장한다. 서류 내용(가정환경, 건강, 연락처)은 저장하지 않는다. 원본 종이는 지금처럼 담임·부서가 보관한다.
- **이름 표시(2026-11-22 확정)**: 담임이 NEIS에서 내려받은 명렬표 엑셀을 **자기 브라우저에서만** 불러와 학번 옆에 이름을 띄운다. 이름은 서버로 보내지 않고 브라우저 메모리에만 둔다(창을 닫으면 사라짐, 원하면 그 기기에만 저장).
- 제출 여부 데이터는 할 일이 완료되고 1개월 뒤 월간 정리(기능 명세 §11.5)에서 삭제하고, "제출률 요약"만 남긴다.

### 4.3 양식(템플릿) 모음

- 학교 공식 양식(기초조사서, 동의서, 가정통신문, 결석신고서, 체험학습 신청서·보고서)을 **양식함**에 버전별로 둔다. 업무 팩 항목에 양식을 연결해 담임이 찾지 않게 한다.
- 가정통신문 초안: 학사일정·업무 팩 데이터로 날짜·장소를 채운 초안을 로컬 LLM이 만들고, 담임이 고친다(예: 담임 인사, 학부모총회 안내).
- 양식은 **NEIS·기재요령 용어 그대로** 쓴다(출결 구분, "출석인정 결석", "교외체험학습" 등). 시스템 코드값도 같은 용어로 둔다.

### 4.4 출결 도우미 — NEIS 입력 전 대조

- 일일 출결 입력 자체는 NEIS에서 한다(이중 입력 방지).
- 시스템은 **출결 서류 추적**만 한다: 학번, 기간, NEIS 구분 코드(결석/지각/조퇴/결과 × 질병/미인정/기타, 출석인정), 서류 상태(신고서·증빙 제출 여부), 제출 기한.
  - **사유·진단명은 저장하지 않는다.** 질병 사유는 기재요령상으로도 보호 대상이다.
- 기한(결석 후 5일)이 다가오는데 서류가 없으면 담임에게 알림(예: "2027-03-15 결석 1건, 결석신고서 기한 D-1").
- 서류가 갖춰지면 **학년부 출결 담당 교사에게 넘길 묶음**(대조표 + PDF)을 만들고, 담당 교사 화면에 반별 제출 현황을 보여준다. 세부 제출 방식은 학교 안내를 받은 뒤 확정한다.
- **월말 마감 체크**: 매월 말 "이번 달 출결 서류 대조표"를 만든다(마감은 다음 달 초). 학번·날짜·구분·서류 상태를 NEIS 출결 화면 순서와 같은 열로 보여주고 엑셀로 내보낸다. 담임은 NEIS와 나란히 놓고 확인한 뒤 마감한다.
- 증빙 기한이 지난 결석은 "미인정 결석 처리 검토 필요"로 표시만 하고, 결정은 담임·학교 규정에 따른다.

### 4.5 엑셀 → NEIS 형식 지원

- NEIS에 엑셀 일괄 올리기가 되는 메뉴와 안 되는 메뉴가 있어 **메뉴별로 확인**이 필요하다. 시스템은 다음까지만 맡는다.
  - 학번 순 정렬, NEIS 화면의 열 순서·용어와 같은 엑셀 내보내기(출결 서류 대조표, 수합 결과, 동아리·임원 명단 등).
  - 명단처럼 이름이 필요한 파일은 §4.2와 같이 **브라우저에서 명렬표와 합쳐** 내려받는다(서버에 이름 없음).
  - 글자수 검사: 학생부 문장(관찰 메모 → 특기사항 초안)의 분량을 NEIS 기준으로 미리 센다. NEIS가 글자수를 바이트로 세는 방식(한글·영문·줄바꿈 가중치)은 2027 기재요령과 NEIS 화면으로 확인 후 반영한다.

## 5. 결석신고서·교외체험학습 서류 간소화

### 5.1 현재 흐름 (종이 → 스캔 → 공문)

```
[결석]       학생 결석 → 보호자 결석신고서·증빙(진료확인서 등) 종이 제출 → 담임 확인
             → 스캔 → (학교에 따라) 공문/내부결재 상신 또는 담임 보관 → NEIS 출결 입력·월말 마감
[교외체험학습] 보호자 신청서·학습계획서 종이 제출(사전) → 담임 확인 → 교감·교장 승인
             → 승인서 전달 → 실시 → 보고서(사진 포함) 제출 → 담임 확인·면담
             → 스캔 → 공문/내부결재 상신 → NEIS 출석인정 결석 처리
```

담임 부담이 큰 단계: 기한 추적(사전 신청·보고서 기한), 승인 진행 확인, 스캔 파일 정리·PDF 합치기, NEIS 반영 누락 확인.

### 5.2 참고: 나이스 학부모서비스 온라인 처리

- 나이스 학부모서비스에서 보호자가 **결석신고서와 증빙**을 올리고, **교외체험학습 신청서**를 작성할 수 있으며, 담임이 NEIS에서 확인·처리한다. 진행 상태(접수대기·처리 중·승인 완료·보완 요청)가 보호자에게 보인다. 종이 출력·보관이 필요 없다고 안내된다.
- 학교가 쓸지 선택할 수 있다(기존 직접 제출도 유지).
- **가장 큰 간소화는 학교가 이 기능을 쓰는 것**이다. 이 시스템은 NEIS와 겹치는 결재 흐름을 새로 만들지 않고, 학교가 종이 방식을 유지하는 동안의 부담을 줄이는 데 집중한다. NEIS 온라인 방식으로 바뀌면 §5.3의 3·4단계는 끄고 기한 추적·월말 대조만 쓴다.

### 5.3 제안 흐름 (종이 유지 학교용)

```
1. 접수   담임이 종이 서류를 휴대폰으로 촬영하거나 복합기로 스캔해 "출결 서류함"에 올림
          (학번·서류 종류만 고르면 됨. 여러 장을 한 번에 올려도 됨)
2. 추출   로컬 OCR/비전 모델이 학번·기간·서류 종류·체험학습 장소 등 항목을 읽어 채움
          → 담임이 확인·수정 (자동 추출은 항상 "초안")
3. 승인   공식 결재는 에듀파인 그대로(2026-11-22 확정). 시스템은 "결재 올릴 묶음 준비"와
          단계별 진행 추적(담임 확인 → 상신 → 승인 완료)만 맡음
4. 묶음   상신할 서류를 학교 규칙대로 PDF 하나로 자동 합침
          (표지 목록: 학번·기간·구분·서류 종류, 파일명 규칙 자동 적용)
          → 담임이 PDF를 내려받아 에듀파인 내부결재에 첨부
5. 반영   승인·보고 완료 건은 "NEIS 출석인정 결석 입력" 할 일로 담임에게 생성
          → 담임이 NEIS 입력 후 체크 → 월말 대조표(§4.4)에 반영
6. 정리   에듀파인 상신이 끝나면 시스템 안 스캔 원본은 삭제(기본 30일 후, 학교 설정)
          → 학번·기간·구분·상태 같은 작은 기록만 남김
```

#### 기한 추적과 알림

| 서류 | 기한 규칙(학교 설정) | 알림 |
|---|---|---|
| 결석신고서·증빙 | 결석 후 5일 이내 | 담임: 기한 D-1, 기한 경과 |
| 체험학습 신청서 | 체험 시작 5일 전까지 | 담임: 기한 내 접수 여부, 승인 대기 2일 경과 시 결재자에게 |
| 체험학습 보고서 | 체험 종료 후 5일 이내 | 담임: 기한 D-1, 기한 경과(미제출 시 출결 처리 검토) |
| 연간 체험학습 일수 | 국내 7일, 국외 30일 | 신청 접수 시 학번별 국내·국외 누적 일수 표시, 초과 시 경고(초과분은 미인정 결석 검토) |

#### 자동 작성

- 담임이 학번·기간만 넣으면 **승인서(허가 통지서)**를 학교 양식으로 채워 PDF로 만든다(이름 칸은 §4.2 방식으로 브라우저에서 채우거나 손으로 기입).
- 보호자에게 보낼 안내문(보고서 제출 기한 포함)도 함께 만든다.

#### OCR·비전 모델 (로컬)

- 외부 API를 쓰지 않는다. Mac mini에서 OCR 엔진 또는 Ollama 비전 모델로 처리한다.
- 업무 중에는 가벼운 OCR만, 무거운 처리는 야간 작업 큐(기능 명세 §8.3, 공문 처리와 같은 큐)에 넣는다.
- 손글씨 인식은 틀릴 수 있으므로 **담임 확인 없이는 확정하지 않는다.**
- 추출 대상은 **학번·기간·서류 종류·체험 장소/유형**만. 이름·진단명·사진 내용은 구조화 데이터로 뽑지 않는다.

#### 보고서 사진

- 체험학습 보고서 사진에는 학생·가족 얼굴이 담기므로 **가장 민감한 자료**다. 시스템에는 상신 PDF를 만들 때까지만 두고, 상신 후 삭제한다. 사진은 질문 자동응답 색인·LLM 학습 예시에 넣지 않는다.
- 열람 권한: 해당 학급 담임, 결재자(교감·교장), 시스템 관리자(감사 로그 기록).

### 5.4 우리 학교 공문(내부결재) 양식 반영 (2026-11-24, 학교 양식 기준)

> 사용자가 올린 "2026 교외체험학습 신청 및 보고서 제출 공문 양식"을 기준으로 정리했다. 양식 속 예시 학생·학교명은 옮기지 않았다.

담임은 체험학습 1건마다 **에듀파인 기안 2건**을 올린다. 아직 다녀오지 않은 체험은 **① 신청 기안만** 만들고, 결과 보고서가 들어오면 그때 ②를 만든다.

학생·보호자 서류는 한 양식 파일 안에 **신청서(서식 1) → 통보서(담임 작성) → 결과 보고서(서식 2, 별지에 사진)** 순서로 들어 있다. 통보서는 **담임이 승인할 때 작성**한다(학교 규정상 통보서 또는 문자 통보 후 실시).

| 기안 | 제목 | 관련 | 본문 항목 | 붙임 |
|---|---|---|---|---|
| ① 교외체험학습 신청 | `교외체험학습 신청(학년-반)` | 학교의 체험학습 운영 기준 공문 번호(학년도마다 1개) | 가. 신청학생 나. 신청기간 다. 신청종류 라. 신청사유 마. 체험학습 신청 현황(표) | 교외체험학습 신청서(학년-반 성*명) 1부 |
| ② 교외체험학습 결과 보고서 제출 | `교외체험학습 결과 보고서 제출(학년-반)` | ①번 신청 기안의 문서번호(모르면 `0000` 자리표시) | "학생 교외체험학습 결과 보고서를 붙임과 같이 제출하고자 합니다." | `붙임  교외체험학습 결과 보고서(학년-반 성*명) 1부.  끝.` — **통보서는 붙이지 않는다**(2026-10 학교 결정) |

**공개 구분 변경(양식의 "변경 전 → 변경 후")**

- 변경 전: 비공개, 제목·본문에 학번(예: `10102`)과 이름.
- 변경 후: **부분 공개**, 제목에는 `학년-반`만, 본문·붙임 이름은 **가운데 글자 마스킹**(예: `김*수`), 학번 대신 `학년-반`.

**본문 서식 규칙**

| 항목 | 서식 | 시스템 처리 |
|---|---|---|
| 신청학생 | `1-1 김*수` | 학번에서 학년-반 자동. 이름은 브라우저 명렬표에서 불러와 마스킹(서버 저장 안 함) |
| 신청기간 | 1일: `2026. 5. 15.(금) (총 1일 간)` / 여러 날: `2026. 9. 17.(목) ~ 9. 20.(일) (총 2일 간)` | 날짜 범위는 실제 체험 전체 기간(주말 포함)을 그대로 쓰고, **"총 N일 간"은 토·일·공휴일·휴업일을 뺀 등교일만** 센다(2026-11-24 확인). 학사일정(NEIS)으로 자동 계산. 신청서의 "총 ( )일간"과 같은 값 |
| 신청종류 | `국내` 또는 `국외` 중 택1 | 선택값 |
| 신청사유 | 신청서 양식의 『학습형태』에 따라 입력(가족동반여행, 친인척방문, 고적답사, 현장체험학습 등) | 신청서의 학습형태 목록에서 선택. 애매하면 담임이 고름 |
| 신청 현황 표 | 누적일수 / 신청일수 / 잔여일수 / 비고(`국내 7일` 또는 `국외 30일`) | 학번별 국내·국외 누적에서 자동 계산. 잔여가 음수면 기안 전 경고 |

**시스템이 해 주는 것**

1. 담임이 학번·기간·국내/국외·학습형태를 넣으면 ①번 기안의 **제목·본문을 양식 그대로** 만들어 준다. 담임은 복사해 에듀파인에 붙여 넣는다(에듀파인 자동 연동은 하지 않음).
2. 담임이 ①번 기안 후 **문서번호**(예: `학교명-2322`)를 입력해 두면, 체험 종료 후 ②번 기안의 "관련"에 자동으로 채운다. 학교 운영 기준 공문 번호는 학년도마다 한 번 관리자가 설정한다.
3. 붙임 파일 이름을 양식 규칙대로 만든다: `교외체험학습 신청서(1-1 김*수).pdf`, `교외체험학습 통보서(1-1 김*수).pdf`, `교외체험학습 결과 보고서(1-1 김*수).pdf`. 스캔본을 올리면 이 이름으로 바꿔 내려받는다(이름은 브라우저에서 붙임).
4. 기한 알림: ①은 체험 시작 5일 전, ②는 체험 종료 후 5일 이내(§5.3 표).
5. ②번 기안이 끝나면 "NEIS 출석인정 결석 입력" 할 일과 학년부 출결 담당 제출 묶음으로 이어진다.

**서버에 남는 것**: 학번, 기간, 국내/국외, 학습형태, 일수, ①·② 문서번호, 단계 상태. 이름·사유 상세·사진은 남기지 않는다.

#### 한글(hwpx) 파일 자동 작성 — 구현 메모

> 사용자가 공유한 "교외체험학습 hwpx 서식 작업 노하우"(이미 실제 학생 서류를 만들어 본 경험)를 바탕으로 정리. 그 문서의 학생 정보·연락처·계정 정보는 옮기지 않았다.

- **양식 파일을 그대로 템플릿으로 쓴다.** hwpx는 zip + XML이므로, 학교 양식(신청서·통보서·결과 보고서·공문)에서 학생 값을 비운 "자동작성 양식"을 만들어 두고 값만 채운다. 학교가 양식을 바꾸면 템플릿만 교체한다.
- **이름이 들어가는 파일은 브라우저에서 만든다.** 서버는 이름 없는 값(학번·기간·일수·학습형태 등)과 템플릿만 주고, 교사 브라우저가 명렬표(결정 1)의 이름을 넣어 hwpx를 완성해 내려받는다. 그래서 서버에 이름이 남지 않는다.
- **서명란은 절대 자동으로 채우지 않는다.** 다른 문서의 서명 이미지를 재사용하면 서명 도용·문서 위조가 된다. 보호자·학생이 직접 서명한 종이를 스캔해 붙이거나, 2단계 온라인 제출에서 본인이 화면에 직접 그린 서명만 그 문서에 쓴다.
- **모르는 값은 지어내지 않는다.** 보호자 이름·관계, 인솔자, 구체 일정, ② 기안의 관련 번호처럼 확인되지 않은 값은 공란이나 `0000` 자리표시로 두고 담임이 채운다.
- **기술적 함정**
  - 같은 라벨("성 명", "년 월 일")이 서식마다 반복되므로 표 칸 좌표(`cellAddr`)로 위치를 정확히 찾는다.
  - 긴 문단(체험학습 계획, 소감)을 바꾸면 `<hp:linesegarray>`의 줄 나눔 정보를 새 글자 수에 맞게 **다시 만들어야** 한다. 옛 값이 남아 있으면 한글이 "문서가 손상되었습니다"를 띄우고, XML 검사·zip 검사로는 잡히지 않는다. 칸 폭과 글자 폭으로 줄을 나눠 lineseg를 새로 만든다.
  - zip으로 다시 묶을 때 `mimetype`은 첫 항목·무압축.
  - 바꾸기가 끝나면 템플릿의 예시 값이 0건 남았는지 확인한다.
- **PDF 변환**: 한글 프로그램으로 열어 저장·PDF 변환하는 것이 가장 정확하다. Mac mini 서버(Docker)에서는 한글 자동화를 쓸 수 없으므로, 1차는 **hwpx만 만들고 담임 PC의 한글로 열어 확인·PDF 저장**한다. 서버 쪽 자동 PDF 변환은 검증된 도구가 생기면 검토한다.
- **누적일수**: 이 시스템의 `field_trip` 기록(학번별 국내·국외)으로 계산하고, 공문 표의 누적·잔여일수와 통보서의 "금회 포함 누적"이 같은 계산을 쓴다.

### 5.5 2단계: 보호자·학생 온라인 제출 창구 (자체 서버, 2026-11-24 확정)

> 결정: Firebase 같은 외부 클라우드는 쓰지 않는다. 온라인 제출 창구를 **학교 Mac mini(PostgreSQL)에 직접** 만든다. 1차 사용자는 교직원뿐이므로 이 창구는 2단계(도메인·HTTPS 외부 공개, 기능 명세 §11.2) 이후에 연다.

**흐름**

```
보호자·학생 (집·휴대폰)                     담임 (교내·집)
1. 담임이 준 링크 + 인증 코드로 접속
2. 신청서 작성 (기간·국내/국외·학습형태·
   계획·인솔자) + 화면에 직접 서명         →  3. 접수 알림 → 내용 확인 → 승인/보완 요청/반려
                                              (승인 시 통보서 작성, 보호자에게 결과 표시)
4. 체험 후 결과 보고서 작성 + 사진 업로드  →  5. 접수 알림 → 확인
                                           →  6. 신청서·통보서·결과 보고서·공문 hwpx 생성(§5.4)
                                              → 한글에서 확인·PDF → 에듀파인 상신
                                           →  7. NEIS 출석인정 결석 입력 할 일, 학년부 출결 담당 제출 묶음
```

- 결석신고서도 같은 창구로 받을 수 있다(기간·구분 + 증빙 사진/PDF 업로드).
- 기한 알림(§5.3 표)은 담임뿐 아니라 보호자 화면에도 보여준다(보고서 제출 D-1 등).

**접속·인증**

- 보호자 계정은 만들지 않는다. 담임이 학생별로 **일회용 링크 + 6자리 인증 코드**를 발급한다(가정통신문·문자로 전달). 링크는 해당 학번·해당 건에만 쓸 수 있고, 건이 끝나거나 기한이 지나면 무효가 된다.
- 로그인 실패 제한(5회), 요청 속도 제한, HTTPS 필수. 교직원 화면과 경로·권한을 분리한다.

**개인정보 — "학번만 저장" 원칙과의 관계**

창구는 서명·보호자 이름·사진처럼 학번 원칙을 넘는 자료를 받는다. 그래서 이 자료는 **임시 제출함**으로 분리한다.

| 자료 | 보관 | 삭제 |
|---|---|---|
| 학번, 기간, 국내/국외, 학습형태, 일수, 단계 상태, 문서번호 | `field_trip`·`attendance_doc` (기존 원칙 범위) | 월간 정리 규칙(§11.5) |
| 학생·보호자 이름, 인솔자, 체험 계획·소감 글, 서명 이미지, 사진, 증빙 파일 | **임시 제출함**(암호화 저장, 해당 담임·결재자만 열람, 감사 로그) | 에듀파인 상신 완료 표시 후 30일, 또는 체험 종료 후 90일 중 빠른 날 자동 삭제 |

- 서명 이미지는 **그 신청서 한 장에만** 쓰고 다른 문서에 재사용하지 않는다.
- 임시 제출함 자료는 질문 자동응답 색인·LLM 분류 예시에 넣지 않는다. 로컬 LLM·OCR도 학번·기간 추출에만 쓴다.
- 보호자 제출 화면에 개인정보 수집·이용 동의(항목, 목적, 보관 기간)를 띄운다. 문구는 학교 개인정보 담당과 확인한다.
- 원본 보관 의무는 에듀파인 상신 문서가 지므로, 이 시스템은 상신 전 작업 공간 역할만 한다.

**나이스 학부모서비스와의 관계**

나이스 학부모서비스에도 결석신고서·교외체험학습 신청 기능이 있다. 학교가 그쪽을 도입하면 이 창구는 끄고 기한 추적·월말 대조만 쓴다. 학교가 종이·에듀파인 방식을 유지하는 동안에는 이 창구가 hwpx·공문 자동 작성까지 이어 주므로 담임 부담을 더 많이 줄인다.
